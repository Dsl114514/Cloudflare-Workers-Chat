● 好的，充米换积分是个大功能，我给你理个 plan。

  ---
  充值系统 Plan

  整体架构

  用户选金额 → 创建订单(DO) → 跳转支付/扫码 → 支付回调 → 确认订单 → 加积分

  涉及的改动：

  ┌──────────┬──────────────────────────────────────────────┐
  │   层级   │                     改动                     │
  ├──────────┼──────────────────────────────────────────────┤
  │ 新 DO    │ PaymentOrder Durable Object — 管理订单状态   │
  ├──────────┼──────────────────────────────────────────────┤
  │ 后端路由 │ CRUD 订单 + 支付回调 webhook                 │
  ├──────────┼──────────────────────────────────────────────┤
  │ 新页面   │ /recharge — 充值页（选金额、支付、订单记录） │
  ├──────────┼──────────────────────────────────────────────┤
  │ 管理后台 │ 查订单、手动补单、配置汇率                   │
  ├──────────┼──────────────────────────────────────────────┤
  │ 积分联动 │ 支付成功后自动调 /points/add                 │
  └──────────┴──────────────────────────────────────────────┘

  详细设计

  1. 订单 DO (PaymentOrder)

  - 每个订单一个 DO 实例（或按用户分片）
  - 字段：orderId, userId, amount(¥), points(积分), status, createdAt, paidAt, 
  payUrl
  - 状态流转：pending → paid / expired / cancelled
  - 订单过期时间：30 分钟

  2. 支付接入

  推荐用 支付宝当面付（扫码支付） 或 微信 Native 支付，流程：

  用户选金额 → POST /api/recharge/create → 后端生成订单 →
  调支付宝API获取二维码链接 → 返回给前端展示二维码
  前端轮询 /api/recharge/check?orderId=xxx → 直到 paid 或过期
  支付成功后 → 自动调用 points/add 给用户加积分

  如果需要更简单（不实际对接支付网关），可以降级为：
  - 充值码系统：管理员后台生成充值码（如 CH-XXXX-XXXX），用户在前端输入兑换
  - 手动充值：用户转账后，管理员在后台手动确认加积分

  3. 汇率设计

  ┌─────────┬────────┐
  │ 金额(¥) │  积分  │
  ├─────────┼────────┤
  │ 5       │ 5000   │
  ├─────────┼────────┤
  │ 10      │ 12000  │
  ├─────────┼────────┤
  │ 30      │ 40000  │
  ├─────────┼────────┤
  │ 50      │ 70000  │
  ├─────────┼────────┤
  │ 100     │ 150000 │
  └─────────┴────────┘

  汇率可配（管理员后台改）。

  4. 前端页面 /recharge

  - 顶部：用户当前积分显示
  - 金额选择：预设档位 + 自定义输入
  - 支付方式：支付宝 / 微信（如果有）
  - 扫码区域 / 跳转按钮
  - 订单记录：最近 20 笔（时间、金额、状态）

  5. 后端新增路由

  ┌────────────────────────────────────────┬───────────────────────────────┐
  │                  路由                  │             说明              │
  ├────────────────────────────────────────┼───────────────────────────────┤
  │ POST /api/recharge/create              │ 创建订单，返回支付链接/二维码 │
  ├────────────────────────────────────────┼───────────────────────────────┤
  │ GET /api/recharge/check?orderId=       │ 检查订单状态                  │
  ├────────────────────────────────────────┼───────────────────────────────┤
  │ POST /api/recharge/callback            │ 支付回调 webhook              │
  ├────────────────────────────────────────┼───────────────────────────────┤
  │ GET /api/recharge/history?name=        │ 用户充值记录                  │
  ├────────────────────────────────────────┼───────────────────────────────┤
  │ POST /api/admin/recharge/confirm       │ 管理员手动确认订单            │
  ├────────────────────────────────────────┼───────────────────────────────┤
  │ POST /api/admin/recharge/code/generate │ 生成充值码                    │
  └────────────────────────────────────────┴───────────────────────────────┘

  6. 涉及新增文件

  src/recharge.html              — 充值页面
  src/recharge.mjs               — 后端路由处理
  src/client/recharge/index.js   — 前端充值逻辑
  src/client/admin/recharge.js   — 管理后台充值管理

  安全注意事项

  - 支付回调必须验签（防伪造）
  - 订单幂等性（一个订单只能加一次积分）
  - 金额下限（最少充 1 元）
  - 汇率只能管理员改
  - 充值码用密码学随机数生成，单次使用

  ---
  实现优先级

  ┌──────┬───────────────────────────────────────┬────────────────┐
  │ 阶段 │                 内容                  │     工作量     │
  ├──────┼───────────────────────────────────────┼────────────────┤
  │ P0   │ 充值页面 + 手动确认（后台补单）       │ ~3h            │
  ├──────┼───────────────────────────────────────┼────────────────┤
  │ P1   │ 充值码系统（管理员生成码 → 用户兑换） │ ~2h            │
  ├──────┼───────────────────────────────────────┼────────────────┤
  │ P2   │ 对接真实支付宝/微信支付               │ 看你有无商户号 │
  └──────┴───────────────────────────────────────┴────────────────┘

  建议：先 P0 + P1 上线，P2 等有商户号再加。
